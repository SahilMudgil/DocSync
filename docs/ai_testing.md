## 3. CodiumAI / Qodo Test Extension Protocol

Students use the **CodiumAI (Qodo)** or **Codeium** VS Code extension to generate additional unit tests for four core modules:
1. `docsync/ingest/git_changes.py`
2. `docsync/eval/metrics.py`
3. `docsync/drift/rule_based.py`
4. `docsync/ingest/doc_parser.py`

### Testing Workflow:
1. Open the target module in VS Code.
2. Launch CodiumAI / Qodo panel $\to$ **"Generate Tests"**.
3. Select edge cases, property-based tests, and boundary values.
4. Run the generated tests using `pytest`.
5. Fix erroneous mock expectations or syntax errors generated by the AI tool.
6. Commit valid tests and record AI hallucinations or mistakes below.

## 5. Critical Analysis of AI Tool Mistakes & Hallucinations

*Record real mistakes made by CodiumAI / Qodo during generation to demonstrate rigorous engineering evaluation:*

1. **Mistake 1 (Flawed Mock / Fixture):**
   - *Tool Observation:* CodiumAI generated a test assuming `git diff` produces stdout formatted with tabs instead of space delimiters.
   - *Engineering Correction:* Updated mock string to reflect standard unified diff output syntax (`@@ -1,1 +1,1 @@`).

2. **Mistake 2 (Non-Deterministic Assertion):**
   - *Tool Observation:* CodiumAI attempted to assert floating point equality on Wilson interval outputs with 8 decimal places (`assert lower == 0.29931849`).
   - *Engineering Correction:* Replaced with range interval assertions (`assert 0.29 <= lower <= 0.31`) or `pytest.approx`.
